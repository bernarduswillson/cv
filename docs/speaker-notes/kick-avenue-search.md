# Kick Avenue: Search and product discovery

**Keynote:** I optimized OpenSearch size matching and facet fallbacks. A production-pod benchmark for a sneaker query with three size IDs went from approximately 10.2 seconds to 1.1 seconds after both changes. Search volume is separately estimated at approximately 350,000 daily requests using sampled search shares and Grafana traffic.

**Optimization and benchmark scope:** [PR #978](https://github.com/kickavenue/be-api-laravel/pull/978) restricts Painless size-trimming scripts to whitespace/Unicode candidates using indexed terms, and retries only the category aggregation when its preferred field returns no buckets. Completed facets and composite pages are reused. The size change reduced measured service time from about 10.2 seconds to 2.3 seconds. The fallback comparison reduced it from 2.18 seconds to 1.12 seconds and OpenSearch calls from 12 to 7, with identical data in all three fallback runs. These are representative multi-size aggregate-query measurements, not an across-the-board search latency reduction or a user conversion experiment. The separate 127 ms median below covers sampled search API requests and is not the baseline for this optimization.

**Calculation and scope:** Four October 27, 2026 samples from all three ingress pods captured **11,927 requests in 37 minutes**, limited to `GET /search` and `GET /prod/search` reaching the Octane API. Search represented **8.5-10.4%** of the simultaneous Caddy all-endpoint counts. Linearly interpolate these shares between sample midpoints, including overnight, then weight them by Grafana's 15-minute traffic profiles and daily totals for **September 27-October 26**. The model averages **350,393.64 search requests/day**, rounded to **350,000**. It assumes the observed shares represent other days and unsampled hours. Pooling **11,873 HTTP 200** ingress durations gives the separately measured **127 ms median**. Cache hits and misses are combined. Daily volume is modeled, while latency covers the sampled windows.
